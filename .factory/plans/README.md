## Findings considered and rejected

- Radix tree: handlers are affine closures rebuilt per request, so a tree
  would be rebuilt per request too and cost more than the linear scan; a
  shared tree cannot hold the handlers. Revisit only with a benchmark
  showing routing above a few percent of a request.
- Optional segments (`:name?`): complicate conflict detection and `Allow`
  computation for little gain; register two routes or use `*rest`.
- Specificity ordering (static beats param): first match wins stays; the
  conflict check turns a shadowed duplicate into a startup error.
- `any`-method routes: deferred until middleware (Tier 4) shows a need.
- Raw-buffer and streaming request bodies: `TCP.recv` returns UTF-8 text
  (no byte-level receive in Bend 2.0.10) and bodies are read whole under
  the body limit before the handler runs. Revisit when the runtime gains a
  bytes receive.
- Nested query keys (`a[b]=1`, `a[]=2`): kept flat; a bracketed key is a
  literal key. Apps that need nesting parse it themselves.
- Compression: the runtime has no zlib or brotli effect, and a deflate
  implementation in Bend is a project of its own. Like TLS, compress at the
  proxy (nginx, Caddy); document in README at 008 time.
- `Last-Modified` and `If-Modified-Since`: `File` has no stat effect, so
  mtime is unknown. ETag from content covers conditional requests.
- Multi-hop proxy trust (hop counts, trusted CIDRs): single trusted proxy
  only in 006; the peer address is unknown to Bend anyway.
