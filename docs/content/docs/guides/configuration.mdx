title: Configure Air from the environment
description: Read the port, limits, and timeouts from environment variables with serve_env, keep app settings in a .env file, and read settings in a handler.
---

This guide shows how to set an Air server up from environment variables
and how to read your own settings. For every variable and default, see
the [Settings reference](/docs/reference/settings).

## Serve the app with settings from the environment

To read the server settings from the environment, serve the app with
`Air.serve_env` instead of `Air.serve`:

```python
def main() -> IO(Unit):
  Air.serve_env(~app, 8080)
```

`Air.serve_env` serves on `PORT`, or on the port in the code when `PORT`
is unset. It also reads the `AIR_MAX_*` limits, the `AIR_TIMEOUT_*`
timeouts, and `AIR_DRAIN_DELAY`. To change them, set the variables when
you start the app:

```bash
PORT=9090 AIR_MAX_BODY=10485760 bend main.bend
```

For an app that takes the stop switch, use
`Air.serve_env_until(~app, switch, 8080)`. See
[Run Air in production](/docs/guides/deploy).

## Fix a bad value

When a server variable has a value that is not a number, the process
stops before it listens. The message names the variable:

```text
air: config: AIR_MAX_BODY is not a number: "1e3"
air: config is invalid
```

Set the variable to digits only, such as `AIR_MAX_BODY=1000`. An unset or
empty variable takes its default.

## Keep app settings in a .env file

To keep the settings of your app in a file, create `.env` in the folder
where you start the app:

```bash title=".env"
# comments and blank lines are skipped
DATABASE_URL=postgres://localhost/app
export GREETING="Hello there"
TAGLINE='single quotes work too'
```

`Air.serve_env` loads this file at startup. The process environment wins
over the file, so `GREETING=Hi bend main.bend` replaces the value in the
file. The server variables, such as `PORT`, come only from the process
environment, not from the file.

<Callout type="warn">
Do not commit `.env` to version control. The `.gitignore` of the Air
repository already excludes it.
</Callout>

When Air cannot read a line, it prints the line number and skips the line:

```text
air: .env:3: ignored
```

## Read a setting in a handler

To read a setting in a handler, call `Air.Config.get` with a name and a
fallback. It returns the environment variable, else the `.env` value, else
the fallback:

```python
def greeting.fin(g: String) -> IO(Air.Response()):
  IO.pure(Air.Response(), Air.Response.text(g))

def greeting(req: Air.Request()) -> IO(Air.Response()):
  IO.bind(String, Air.Response(), Air.Config.get(req, "GREETING", "hi"), greeting.fin)
```

```bash
curl localhost:8080/config/greeting
```

```text
Hello there
```

The app is a closed template, so a value that `main` reads cannot reach a
handler. `Air.serve_env` puts the `.env` values in the store, and each
request carries the store. Each call reads one variable and takes the
store lock one time, so do not call it in a loop.

## Read a setting in main

To read a setting before the server starts, call `Air.Config.env` for a
string or `Air.Config.u32` for a number:

```python
def main() -> IO(Unit):
  do IO<Unit>:
    workers : U32 <- Air.Config.u32("WORKERS", 4)
    IO.print("workers: " ++ U32.show(workers))
    Air.serve_env(~app, 8080)
```

`Air.Config.u32` stops the process when the value is not a number, like
the server variables.

## Load the .env file with serve_shared

`Air.serve_shared` does not read the environment. To use `Air.Config.get`
with it, load the file and put it in the store yourself:

```python
def serve(store: Air.Store()) -> IO(Unit):
  +store = store
  do IO<Unit>:
    cfg : Air.Config() <- Air.Config.load(".env")
    Air.Config.install(store, cfg)
    limits : Air.Limits() <- Air.Limits.from_env()
    timeouts : Air.Timeouts() <- Air.Timeouts.from_env()
    port : U32 <- Air.Config.port(8080)
    switch : Air.Switch() <- Air.Switch.new()
    Air.serve_shared(~app, limits, timeouts, store, switch, port)

def main() -> IO(Unit):
  IO.bind(Air.Store(), Unit, Air.Store.new(), serve)
```

`serve` rebinds the store with `+`, because it uses the store two times.
`Air.serve_shared` takes an app that receives the stop switch.

## Keep secrets out of logs

Air never prints the value of a variable whose name contains `SECRET`,
`TOKEN`, `KEY`, or `PASSWORD`, in any letter case. An error message shows
`<hidden>` instead. Put one of these words in the name of each secret.
