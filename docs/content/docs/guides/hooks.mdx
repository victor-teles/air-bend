---
title: Add lifecycle hooks
description: Run code at a point in the request lifecycle with Air hooks, the Air form of Fastify's onRequest, preHandler, onSend, onResponse, and onError.
---

A hook runs a function at one point in the life of a request. In Air, a
hook is a middleware that takes a plain function instead of `next`. The
hook calls the rest of the chain for you, so your function cannot skip the
handler or call it two times. Where you put the hook decides when it runs.

## Choose a hook

| Air | Fastify name | Your function receives | Your function returns | Runs |
| --- | --- | --- | --- | --- |
| `Air.on_request(f)` in `Air.use` | onRequest | The request | A request | Before routing |
| `Air.on_request(f)` in `Air.Route.wrap` | preHandler | The request, with path parameters | A request | After routing, before the handler |
| `Air.on_send(f)` | onSend | The request and the response | A response. Air sends it. | After the handler |
| `Air.on_response(f)` | onResponse | The request, the response, and the milliseconds | `Unit` | After the handler. The response does not change. |
| `Air.on_fail(f)` | onError | The request and the error | `Unit` | After the handler, only for a failed response. The response does not change. |

## Add hooks to the app

This app adds a header to each response, prints the time of each request,
and reports each error:

```python
def stamp(req: Air.Request(), res: Air.Response()) -> IO(Air.Response()):
  IO.pure(Air.Response(), Air.Response.with_header(res, "x-served-by", "air"))

def record(req: Air.Request(), res: Air.Response(), ms: Nat) -> IO(Unit):
  IO.print(Nat.show(ms) ++ " ms")

def report(req: Air.Request(), e: Air.Error()) -> IO(Unit):
  IO.print("failed: " ++ U32.show(Air.Error.status(e)))

def app(req: Air.Request()) -> IO(Air.Response()):
  Air.use([
    Air.request_id,
    Air.on_response(record),
    Air.on_send(stamp),
    Air.on_error(Air.Error.plain(Air.Env.prod())),
    Air.on_fail(report)
  ], base)(req)
```

The first middleware in the list runs first before the handler and last
after it. So the order in this example matters in two places:

- `Air.on_fail` is inside `Air.on_error`, so it sees the error before
  `Air.on_error` renders it.
- `Air.on_send` is outside `Air.on_error`, so it sees the rendered
  response. A rendered error keeps the headers of the failed response, so
  a header that `on_send` adds stays on either side.

## Add a preHandler hook to a route list

To run a hook after routing, when the path parameters are ready, wrap a
route list with `Air.on_request`:

```python
def load_user(req: Air.Request()) -> IO(Air.Request()):
  +req = req
  IO.pure(Air.Request(), Air.Request.with_local(req, "user", Air.Request.param(req, "id")))

def user_routes() -> List<Air.Route()>:
  Air.Route.wrap(~Air.on_request(load_user), [Air.Route.get("/users/:id", show_user)])
```

The handler reads the value with `Air.Request.local(req, "user")`.

## Stop a request early

`Air.on_request` cannot respond by itself. For a check that must stop the
request, such as authentication, write a middleware that does not call
`next`. See [Write middleware](/docs/guides/middleware).

## Keep hooks cheap

A hook that writes to the store takes the store lock one time for each
request. Put such hooks on the route lists that need them, not on the
whole app. The `/hooks` routes in `examples/hello/app.bend` show this.

## What Air does not have

- **A hook after the write.** The server owns the socket, and app code
  runs before the server writes the response. `Air.on_response` runs when
  the app has its response. The app never sees a write that fails.
- **A hook registry.** Bend cannot copy a function, so a list of
  callbacks that Air consults for each request does not work. The order of
  middleware does the same job.
