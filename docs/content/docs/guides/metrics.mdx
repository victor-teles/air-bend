---
title: Expose metrics
description: Count requests and measure latency for each route of an Air app, serve the numbers in the Prometheus text format, and add your own counters.
---

`Air.metrics` counts each request by method, route, and status, and it
measures how long each request takes. `Air.Metrics.expose` serves the
numbers in the Prometheus text format. Prometheus, Grafana Agent, the
OpenTelemetry Collector, and VictoriaMetrics can read this format.

## Add metrics to an app

1. Put `Air.metrics` first in `Air.use`, so that its time covers the whole
   chain:

```python
def app(req: Air.Request()) -> IO(Air.Response()):
  Air.use([Air.metrics, Air.request_id, Air.log], base)(req)
```

2. Serve `Air.Metrics.expose` on a route that only you can reach. The
   output names every route, so put it behind an auth middleware or on a
   path that your proxy does not expose:

```python
def routes() -> List<Air.Route()>:
  Air.Route.all([
    app_routes(),
    Air.Route.mount("/admin", Air.Route.wrap(~auth("secret"), [
      Air.Route.get("/metrics", Air.Metrics.expose)
    ]))
  ])
```

3. Send some requests, then read the metrics:

```bash
curl -H 'x-token: secret' localhost:8080/admin/metrics
```

```text
# HELP air_http_requests_total Requests answered, by method, route and status.
# TYPE air_http_requests_total counter
air_http_requests_total{method="GET",route="/hello/:name",status="200"} 12
# HELP air_http_request_duration_seconds Time in the app, from the middleware's view.
# TYPE air_http_request_duration_seconds histogram
air_http_request_duration_seconds_bucket{route="/hello/:name",le="0.005"} 10
air_http_request_duration_seconds_bucket{route="/hello/:name",le="0.01"} 12
...
air_http_request_duration_seconds_bucket{route="/hello/:name",le="+Inf"} 12
air_http_request_duration_seconds_sum{route="/hello/:name"} 0.042
air_http_request_duration_seconds_count{route="/hello/:name"} 12
```

4. Point your scraper at the route. Scrape every instance, because each
   process keeps its own counts.

## Read the labels

The `route` label is the pattern of the route that ran, with its mount
prefix, such as `/admin/users/:id`. So `/users/7` and `/users/8` count as
one series. The label is `""` when no route ran, for example for a 404 or
a CORS preflight.

A method that Air does not know is `OTHER`, so a client cannot add
series. The `status` label is the status of the response. For every label
and bucket, see the
[Observability reference](/docs/reference/observability#metrics).

## Query the metrics

To get the rate of 5xx responses for each route, use:

```text
sum by (route) (rate(air_http_requests_total{status=~"5.."}[5m]))
```

To get the 99th percentile latency for each route, use:

```text
histogram_quantile(0.99, sum by (le, route) (rate(air_http_request_duration_seconds_bucket[5m])))
```

## Count your own events

To count an event of your app, call `Air.Metrics.count` in a handler:

```python
def signup.fin(u: Unit) -> IO(Air.Response()):
  IO.pure(Air.Response(), Air.Response.with_status(Air.Response.text("welcome"), 201))

def signup(req: Air.Request()) -> IO(Air.Response()):
  IO.bind(Unit, Air.Response(), Air.Metrics.count(req, "signups"), signup.fin)
```

This call adds one to `app_signups_total`. The name must match
`[a-z0-9_]+`. Air ignores any other name, so a typo cannot break the
output. App counters have no labels.

## What Air does not count

Air does not count a server refusal, such as a head that is too large, a
malformed request, or an app timeout (503). The app does not run for
these requests. The server prints a line for each one instead.

## How Air keeps the numbers

The counts are in the `metrics` namespace of the store. Each request takes
the store lock one time. A restart sets the counts to zero, and the
Prometheus `rate()` function handles the reset.

The router puts the route pattern on the response, and `Air.metrics`
reads it there. The server removes it before it writes the response, so
it never reaches a client. Your own middleware can read it with
`Air.Response.route(res)`.

The number of series grows with the number of routes, times the methods
and statuses of each route. A fixed route list keeps the count bounded.
