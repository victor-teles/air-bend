---
title: Publish an OpenAPI document
description: Describe Air routes with notes, validate requests with the same schemas, and serve an OpenAPI 3.1 document for client generators and API explorers.
---

A route can say what it takes and what it returns. `Air.openapi` turns a
route list into an [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0)
document. Client generators, API explorers, and contract tests read this
document.

## Describe the routes

1. Write the schemas in defs. See [Validate requests](/docs/guides/validation).
2. Add notes to each route. Each note is a def that takes a route and
   returns it with the note, so you nest the calls:

```python
def api() -> List<Air.Route()>:
  [
    Air.Api.tag("tasks",
      Air.Api.summary("List tasks",
        Air.Api.returns(200, Air.Schema.arr(task()),
          Air.Api.query(tasks_query(), Air.Route.get("/tasks", tasks))))),
    Air.Api.tag("tasks",
      Air.Api.summary("Create a task",
        Air.Api.returns(201, task(),
          Air.Api.body(new_task(), Air.Route.post("/tasks", create)))))
  ]
```

| Note | Validates | Adds to the document |
| --- | --- | --- |
| `Air.Api.body(schema, route)` | The JSON body | The request body, and the 400 and 422 responses |
| `Air.Api.query(schema, route)` | The query | One query parameter for each field of the object schema |
| `Air.Api.returns(status, schema, route)` | Nothing | A JSON response |
| `Air.Api.summary(text, route)` | Nothing | The summary |
| `Air.Api.tag(name, route)` | Nothing | A tag |

You write each schema one time, so the document cannot drift from what
the route accepts.

## Serve the document

A route list cannot contain a route that describes that same list. So
build the described list in its own def, and call the def two times:

```python
def routes() -> List<Air.Route()>:
  Air.Route.all([
    api(),
    [Air.Route.get("/openapi.json", Air.openapi("Tasks", "1.0.0", api()))]
  ])
```

```bash
curl localhost:8080/openapi.json
```

```text
{"openapi":"3.1.0","info":{"title":"Tasks","version":"1.0.0"},"servers":[{"url":"/"}],"paths":{"/tasks":{"get":{"operationId":"get_tasks","summary":"List tasks",...
```

Each request can build `api()` two times. Notes are plain values, and Air
renders the JSON only for a request to `/openapi.json`. If routing shows
up in a profile, write the document to a file with `Air.Api.document`
and serve the file.

## Describe path parameters

You do not add notes for path parameters. Air lists each `:name` and
`*name` of the pattern as a required string parameter. A `*name` also
gets a note that it can contain `/`, because OpenAPI has no parameter
for more than one segment.

## Mount described routes

Mounting keeps the notes. `Air.Route.mount("/api", api())` documents
`/api/tasks`.

## Show the document in a browser

Swagger UI and Redoc are static pages. Serve one with
[`Air.static`](/docs/guides/static-files), and point it at
`/openapi.json`.

## What the document does not include

The document has no security schemes, examples, `$ref` reuse, header or
cookie parameters, or YAML output. A linter rule that wants security on
each operation reports a warning. The document does not list the HEAD and
OPTIONS responses that the router makes, but it lists the routes that you
add with `Air.Route.head` and `Air.Route.options`.

For the contents of the document in detail, see
[What the document contains](/docs/reference/schema#what-the-document-contains).
