This page is for contributors to Air. It lists the checks to run before a
commit and the jobs that CI runs.

## Run the checks before a commit

Run these commands from the repository root:

1. Prove the laws:

```bash
bend PROOF.bend
```

   The output must contain `All terms check.`

2. Run the tests:

```bash
bend tests/hello.bend
bend tests/dashboard.bend
```

   Each test prints one line for each assertion and exits with code 1
   when an assertion fails. Each one takes about 25 seconds to start. To
   run them faster, build them natively. See
   [Run the tests natively](/docs/guides/testing#run-the-tests-natively).

3. When you changed the docs, build them:

```bash
cd docs
pnpm build
```

## CI jobs

`.github/workflows/ci.yml` runs on every pull request and on every push to
`main`:

| Job | Checks |
| --- | --- |
| Proof | `bend PROOF.bend` prints `All terms check.` |
| Tests | Each `tests/*.bend` is built natively and runs. A native build starts at once. |
| Native builds | `examples/hello` and `examples/dashboard` build with `bend -o`. The C backend refuses two defs whose names become the same C symbol, and only a native build finds this error. |
| Docs build | `pnpm build` in `docs/` succeeds. |
| Benchmark | Pull requests only. See [Benchmarks](/docs/project/benchmarks). |

## Change the Bend version in CI

`.github/actions/setup-bend/action.yml` pins Bend. It installs one
release, checks its sha256, and installs clang 19 for native builds. To
move CI to a new Bend release:

1. Change the `version` input to the new release.
2. Change the `sha256` input to the sha256 of
   `bend-<version>-linux-x64.tar.gz` for that release.
3. Run the checks in
   [Run the checks before a commit](#run-the-checks-before-a-commit) with
   the new release.
